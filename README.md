# kihyun-skills

Personal collection of [Claude Code](https://claude.com/claude-code) and [Codex](https://openai.com/codex/) skills.

Each top-level folder containing a `SKILL.md` is one skill. This repo is the
single source of truth; skills become active by linking them into each agent's
skill directory, where Claude Code and Codex discover them.

## Skills

| Skill | What it does |
| --- | --- |
| [`thegraph-codex`](thegraph-codex/) | Codex-native, explicitly invoked version of thegraph's end-to-end discipline: establish the task from repository guidance and primary sources, make routine implementation decisions autonomously, ask only for consequential product or scope decisions, prove behavioural tests can fail, then run verification proportionate to the changed surface. It does not require Claude Code platform skills or create external tracker records without an explicit request. |
| [`to-html`](to-html/) | Convert a markdown file — or content already in the conversation — into a single self-contained, styled HTML file: inline CSS, sticky table of contents, callouts, premium layout blocks. No build step. |
| [`brief`](brief/) | Explain the work in flight to the person who has to decide about it — state, the next action, what it changes **and what it leaves alone**, and what they must decide (including "nothing", which is information). Publishes a one-screen Artifact with its own briefing layout; falls back to chat when there is no structure worth laying out. Status claims are queried with `gh`/`git` rather than copied out of the conversation, and measured facts are marked apart from inferred ones. Vocabulary is governed by a structural check — every noun must point at something the user can see or do — not by a banned-word list, because the words that lose someone next are never the ones already on the list. A view, never a source: nothing may exist only in a briefing. Invoked only (`/brief`, `/brief <issue>`, `/brief session`) — judging whether someone understands you is not yours to do. |
| [`gate`](gate/) | The Acceptance Gate — review an AFK agent's finished work on an issue, render a verdict (Pass / Rework / Respec / Escalate) with the matching next action, and run it on the tracker once you approve. Delegates the diff review to the `code-review` skill. |
| [`to-deck`](retired/to-deck/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0059](docs/adr/0059-to-deck-is-retired.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** Turned a study PDF into a reusable JSON question bank through an interactive Korean Q&A session: keeps the workbook's own questions in order (`origin: workbook`) and adds generated extras (`origin: extra`) — a mix of explanatory and single-term recall questions — each a plain `{question, answer}` pair. Offers a one-at-a-time session or batch extraction; no question-type labels — a downstream tool classifies them. |
| [`grill-code`](retired/grill-code/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0058](docs/adr/0058-grill-code-is-retired.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** Grilled code along one chosen mode — security, common-component extraction, refactoring, performance, or learning — scanning the scope relentlessly. Defect modes score each finding on severity + effort and rank them by priority (P0–P3); the non-defect learning mode explains AI-written code as Lessons ranked by Value. Report only; standalone (no dependency on `code-review`/`audit`). Can save the report as HTML via `to-html`. |
| [`img-to-pdf`](img-to-pdf/) | Combine a folder of images (or an explicit file list) into one PDF, one image per page, in natural-sort order (`2.jpg` before `10.jpg`). **Default: a searchable PDF** — the page image plus an invisible, selectable/searchable text layer via macOS Vision OCR (Korean + English). `--image-only` instead embeds JPEG/PNG losslessly with no text layer (HEIC/HEIF/WEBP pre-converted via `sips`; `img2pdf` auto-installed into a cached venv). OCR mode is macOS-only; the Swift helper compiles once and caches. |
| [`theflow`](retired/theflow/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** The seven-step working discipline for a substantive change to a boundary-defined codebase, succeeded by [`thegraph`](thegraph/) which carries every rule it held (ADR-0019). Kept readable because the `docs/agents/theflow.md` bindings it read still exist in the repos it onboarded — no skill compiles them now, that path having gone with [ADR-0067](docs/adr/0067-the-theflow-migration-path-is-gone.md); `grill-the-graph` reports one and `salvage` clears it on request ([ADR-0094](docs/adr/0094-an-older-build-is-found-by-its-stamp.md)). |
| [`grill-the-flow`](retired/grill-the-flow/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** The setup half of `theflow` — it interrogated a maintainer to author the repo's `docs/agents/theflow.md` bindings. Succeeded by [`grill-the-graph`](grill-the-graph/), which asks a much smaller question and writes a much smaller file. Nothing reads the bindings docs it wrote, that path having gone with [ADR-0067](docs/adr/0067-the-theflow-migration-path-is-gone.md). |
| [`read-it`](read-it/) | Read the situation before touching anything, and come back with a **route**. The first act of a change and the only one whose mistakes nothing downstream catches — a wrong proof method fails at the proof and a wrong placement fails at the diff, while **a wrong reading of the issue passes everything**, a run that solves the wrong problem well having still solved something well. Four reads, three of them conditional on something you **check rather than weigh**: the build (short, and answering little on purpose); the cluster, where one tracker query finds a parent (the anchor's root is a hypothesis to test, and what siblings rejected is read before anything is re-proposed); the territory map where the repo keeps one; and always the real sources plus the hidden state (`firsthand`, one reflex rather than two — the source list widens what you read, it never decides *whether* you read, and with no outside source named you still enumerate the hidden state of the code you are touching). Doing one of the four and doing all four are both ordinary; what is not is skipping one and being unable to say why. Then **restates the issue in its own words and stops to ask** — the only guaranteed stop, since every later one is conditional and a run where nothing goes wrong first reaches a person with the work already done and nowhere to have redirected it. Returns a route **label**, never a skill name, so what runs next stays the caller's to decide. Everything it finds is a candidate; nothing reaches a tracker unasked. Its regression cases — closed issues with a known outcome, run through `/thegraph` and again with no skill loaded — sit beside it in `read-it/evals/` ([ADR-0087](docs/adr/0087-thegraph-reading-step-has-a-regression-suite.md)). |
| [`make-it`](make-it/) | Write the change. Calls `tdd` for the tests and then watches every one of them fail — name the assertion, turn the change off, see it go red, restore — **a green from a test nobody watched fail is not evidence**, which is the one thing `tdd` does not do. Keeps the narrow exception where compilation itself enforces completeness and a round-trip test replaces strict RED, and the rhythm a whole-suite-at-the-end habit loses: typecheck and the nearby tests often, everything once at the end. Prose changes walk it too, with the test section conditional. Carries the rule that **a comment says what the code is**, and follows the repo's `CLAUDE.md` for where the rest goes rather than holding its own copy — comments are written on every edit, and most edits never pass through `make-it`. Its substance is the **four signals that only appear while your hands are in the code**, since you cannot schedule the moment you will feel one: *"this is a bit odd, I'll just fix it up here"* — the tell that the problem is one step further in, tempting because it works and costs nothing visible, until the day somebody fixes the real thing and every patch like it becomes silently wrong; a new file with no obvious home; an outside fact about to be written from memory rather than read (a version, a *"supported since"*, a platform's behaviour, somebody else's claim), local source first; and a call that is the maintainer's. What you notice and do not fix is carried, never filed. |
| [`check-it`](check-it/) | Measure a finished change before anyone calls it done — **the hand that shaped a thing is the worst judge of whether it is finished**. Eight checks, ordered by cost rather than ceremony, each conditional: the gates bare (no pipe, the list from CI, a threshold never moved), whether new or moved files landed where the layout rule said, proof against something real rather than a fake, the diff read by one fresh agent for standards, for what the issue asked and for exposure, each answered apart (ADR-0095), and for cost with a number or not at all, the whole corpus read for what is missing (`lens`), and the surfaces that describe the behaviour (`sweep`). A prose change runs the last two and nothing else. **One question runs through all of it** — a red, a defect, a defensive line: is it mine? Answered by re-running against the tree without this change and **comparing the failure, never the exit code**, since a baseline red for its own reason makes every red compare `1` to `1` and inverts the attribution silently. And one shape is hunted assuming the writer left no help at all, because whoever did not notice could not have written it down: for each defensive line, *what would have to be true for this to be unnecessary?* — if the answer names something you did not change, that is where it belongs. Fixes nothing; measures, attributes, hands on. |
| [`pub-ready`](pub-ready/) | Bring a Dart or Flutter package to the point where only `pub publish` is left — **the maintainer's release bar, held once** instead of in each package's `CLAUDE.md`, where it had been copied into at least seven packages and drifted ([ADR-0086](docs/adr/0086-the-pub-dev-release-bar-is-one-skill.md)). Reads what pub.dev already has first, raw from its API, since that settles whether the version is new, which CHANGELOG entries are frozen and what changed since the last release. Then pubspec (version size against the diff, the `0.x` caret trap, the SDK floor, fields checked by `pana` itself rather than a copied limit), CHANGELOG (an entry per behaviour change, a published one never rewritten), README (every API name it shows grepped in `lib/`), the CI steps plus the gates CI does not reach — `pub get` before `dart format`, the example, the dry-run at **0 warnings on a clean tree** with its file list read — all run bare. **Never publishes**: it ends with the command written out for the maintainer. A package's own guidance adds to it and, where they differ, wins. **Runs only when a release is being prepared, in a repo that chose it**: `grill-the-graph` asks, recommending it for an open-source package, and records `pub-ready` or `None.` in the build, which this reads first. |
| [`winnow`](winnow/) | Cut an always-loaded agent document — `CLAUDE.md`, `AGENTS.md`, a skill body — down to what every run needs. Five bins per paragraph: **rule** stays, **detail** moves behind a pointer that names its trigger, **number** stays only where a decision turns on it, **roster** becomes the command that derives it, **history** leaves for version control. **History is asked last**, and an incident story has its rule extracted before the story goes. Shows the table — every history part quoted, not counted — and **stops for the maintainer**; on approval writes, then proves every rule still has a home by reading the original from version control, and repoints references to moved sections. The case it was cut from is [ADR-0077](docs/adr/0077-an-always-loaded-document-keeps-its-rules-and-history-leaves.md). |
| [`ask-it`](ask-it/) | Put everything that has been carried in front of a person, once, and file only what they keep — **the one door**, since nothing may evaporate into a pull-request body or a code comment, where it is buried on merge. Only what is the person's is asked (naming, scope, direction, spend, the tracker, a push); a technical call is measured, decided and reported. Every item carries five things, a decide item arrives with each option's consequences, and items come one at a time with the count that remains ([ADR-0089](docs/adr/0089-ask-it-absorbs-envelope-and-byartifact.md)). Beyond that, the items arrive from different places with dispositions that **share no vocabulary** — something to file, something to decide, something belonging to another repository, something a release will oblige — and interleaved, the reader classifies before answering, which is the sorting that presenting one at a time was bought to remove. Before anything is opened it searches by the artifact, not the feature name, and only for items actually being filed. In a cluster run each discovered item takes one answer: needed now, needed next run, out of scope under its source, needs design, or drop. A follow-up is **parented through the tracker's own relation in the same act as filing it**, and whether it also joins the cluster is a separate judgement: provenance and root are different claims, and the error is not symmetric — missing a sibling costs a reconstruction, counting an adjacent one **corrupts the roster** that somebody later copies almost verbatim. A release's obligations are the consumer tests that actually broke, **named**; a purely additive release obliges nothing, and that is an answer worth writing. |
| [`thegraph`](thegraph/) | Take one change from an issue to done, in a codebase whose identity is a **boundary** — a core that stays correct by *not* absorbing the concerns of the things that consume it. Four skills in order — [`read-it`](read-it/) → [`make-it`](make-it/) → [`check-it`](check-it/) → [`ask-it`](ask-it/) — with **one guaranteed stop** before any of them run: the reading of the issue, confirmed by the person who holds it, since a change where no signal fires otherwise reaches a person for the first time at the very end, with the work done and nowhere to have redirected it. Two routes after that, and the one that gets missed is expensive: an issue asking for a **choice** gets the adversarial read over the *options* before any proposal, or the enumeration lands after approval and its costs get demoted into follow-ups. Everything else is a **signal you cannot schedule** — the urge to patch around something one step further in, a test just written, an outside fact about to be written from memory rather than read, a call that is the maintainer's — acted on where it arrives rather than noted for later. What holds throughout: nothing reaches a tracker unasked; what can be counted is counted; **a derivation falls to a better derivation and a judgement falls only to the person who made it**, so a record that does not say which it holds reads as the first. Human-invoked (`/thegraph`). Given an issue with open sub-issues (a spec after `/to-tickets`), it runs a **cluster**: the children in blocking order, in one session, with one stop at the start and `ask-it` at the end, the push going through the last one ([ADR-0088](docs/adr/0088-thegraph-takes-a-cluster.md)). |
| [`grill-the-graph`](grill-the-graph/) | The setup half of `thegraph`. Writes one short prose file, `docs/agents/thegraph.md`, holding **what a person already knows and no file in the repo answers** — which is very nearly just the real sources the project is built against, each marked *how it works* or *where files go*, raw or **summarized**, an example to follow or a spec that binds. A line earns its place only by clearing three conditions together: no file here answers it, a person already knows it, and something reads it. The second is the one that used to be missing — *"only a person could decide it"* and *"a person already knows it"* are different sets, and everything this skill once asked for (sacred paths, the tie-breaker, the seams, a proof method per layer) cleared the first and failed the second, so the answers came back drafted by the builder and ratified by someone who could not have produced them. **Generates no scripts and no agents**, carries no build stamp, and copies nothing the repo already states; the build **grows** as runs ask for what it lacks. **Run again, it updates**: where `docs/agents/thegraph.md` exists it keeps the build, asks nothing already answered, and brings what it installed — the comment rule, the map hub, the attribution pieces — and the lines pointing at them up to its current text; `/grill-the-graph init` rebuilds from scratch instead, written only on the maintainer's approval ([ADR-0085](docs/adr/0085-grill-the-graph-runs-again-as-an-update.md)). An older generated build, found by its build stamp or by `scripts/thegraph/` and `.claude/agents/thegraph-*`, is handed to `salvage` rather than read or updated. A project built against nothing outside itself yet answers **none yet**, and the file records that the question was put rather than inventing a row. Where the repo has **no territory map**, it makes the map's folder with a one-line hub instead of building one — the rule needs a destination on disk, and an empty map is a young repo's honest state; notes arrive as edits need them or all at once through [`grill-map`](grill-map/). Then it writes **the comment rule into the repo's `CLAUDE.md`**: a comment says what the code is, with the rest sent to the map, the decision records or the commit message, naming only destinations that exist on disk. That is the one place the rule is written, because comments are written on every edit and a pass that checks them afterwards is undone by the next one. In a repository you **contribute to** rather than own — named by the argument (`/grill-the-graph local`, or `own` for your own), and asked first when there is none, with `viewerPermission` on the receiving repository as the recommendation — it commits nothing: the same file and a rule deferring to upstream's own guidance go in untracked, excluded files, no map is made, and a hook blocks Claude attribution on the way out ([ADR-0079](docs/adr/0079-in-a-repository-you-contribute-to-its-conventions-win.md)). In your own repository attribution stays unless you turn it off when asked, and off installs the same check, locally. In your own repository holding a Dart package for pub.dev, it asks whether [`pub-ready`](pub-ready/) is the release bar — recommending it when the package is open source — records the answer, and on a yes offers to replace each older copy of the bar with a pointer, keeping what only that package has ([ADR-0086](docs/adr/0086-the-pub-dev-release-bar-is-one-skill.md)). |
| [`salvage`](salvage/) | Clear an older `grill-the-graph` build out of a repo without losing the answers a person gave it. The whole job is telling two things apart: what somebody sat down and **answered**, which has to survive, and what was **copied out of the repository**, which is why that build went. Finds what is ours by the **build stamp** every generated file carries, in whichever form, and by the build document's own manifest, and reads both — a stamped file the manifest does not name is the case that matters, the manifest being a copy like any other. Four rings: ours (build doc, generated agents and scripts, the ignore line, and the run-state cache **version control never shows you**); somebody else's file pointing at ours, where only the line comes out — a repo left with a hook invoking a deleted script cannot commit, so clearing the first ring and reporting the second is a break with a note attached; produced by our rules but not written by us, shown and asked, **and any generated file a later commit touched, because that made it theirs**; and outside, untouched — decision records describe the world when they were written, broken links included. Lifts the reference list into the short file the current skill defines, drops the rest with a reason each, and re-reads the tree afterwards, since a cleanup reporting success without looking again has checked nothing. |
| [`tickets`](retired/tickets/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0069](docs/adr/0069-tickets-is-retired.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** Put back what slicing dropped — the third producer in the `thegraph` family. A general slicer keeps a ticket thin because it cannot know who will execute it; here the executor **was** known, so the calls a maintainer had already made travelled with the ticket instead of staying behind in the spec. Ran right after the tickets were cut, in the same unbroken window as the grilling: **transcribed** the settled calls into each ticket, **enrolled** the parent as the relation the tracker actually renders (which is still why the cluster roster is a query and not a body parse), and **marked** each entry `human` / `derived` / `unknown`. It read thegraph's *"What the issue must supply"* at runtime rather than hardcoding it, and that is the one thing it demonstrably bought: the schema went from five slots to six and the producer needed zero edits. Retired on the maintainer's call, with the falsification ADR-0045 had written in advance already fired — on the only run anyone measured, every contract entry was marked `derived`, which licenses nothing. **The schema it filled is live**; `thegraph` reads a contract wherever one is written, and a ticket that answers none of it was always the ordinary case. |
| [`firsthand`](firsthand/) | Read the real thing before you guess, and never promote ignorance into fact — `thegraph`'s `reference` and `enumerate` nodes, which turned out to be one reflex split across two slots ([ADR-0042](docs/adr/0042-a-nodes-method-leaves-its-bound-stays.md)). Fetch raw source and grep the actual lines: **never a summarizing fetch**, because summary drops method bodies and a handler that *is* there reads as absent. A feature being new never excuses skipping its **mechanism layer**, which the reference almost always has. Pin a runtime value with a throwaway probe and record the number — reading code is not observing what it does. Then the exit guard: **unconfirmed is a gap, not an absence.** Re-confirming costs one fetch; guessing wrong costs days. Clear a worry and you record the condition it holds under. Fuses `factchk`. |
| [`sweep`](sweep/) | Every surface that describes the behaviour drifts the moment the behaviour moves, and nothing compiles the drift away ([ADR-0042](docs/adr/0042-a-nodes-method-leaves-its-bound-stays.md)). Doc-comments ship **verbatim** and are the last thing describing a fixed bug as a contract; a published changelog entry is never rewritten, only superseded; a decision record whose premise the change falsified is amended **in that same change**, because a trail only ever read becomes a museum. Reclaim rationale a later change made false. And **judge the pass by what it could not see, never by its hit count** — a low count means the pattern is clean *or* the pattern is narrow, and the number cannot tell you which, so a hit is spent widening the pattern before it is spent on the hit. Fuses `shower`, `re0`, `debloat`, `ssotize`. Where the repo keeps a territory map, its notes are a surface too: the ones naming what the change touched, and one hop out, are brought in line, a fix asks whether its fact holds elsewhere, and a new area is left for `grill-map`. |
| [`promote`](retired/promote/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0070](docs/adr/0070-promote-is-retired.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** Said to write the rule down once the same model had been re-decided twice, on five observable triggers counted across a cluster. Retired on the maintainer's call, with the worry that records would pile up faster than they earned their place. Two things had already made the trigger count unreliable: the `triggers` state slot that fed it was deleted with the rest of thegraph's run state, leaving nothing to count; and this session was a textbook case — the same judgement re-made four times in a row, the skill installed and model-invocable throughout, and it fired not once. **The two-occurrence bar** survived in `sift` for the `SYSTEM` disposition, the one place it was load-bearing; `sift` is retired too ([ADR-0075](docs/adr/0075-sift-is-retired.md)) and nothing live states it. |
| [`lens`](lens/) | The adversarial completeness pass, extracted from `thegraph`'s `verify` node (ADR-0042). **One reader over every corpus at once** — this codebase's siblings and the named prior art — because two readers split across halves buy coverage while calling it independence, and neither can then say which of two disagreeing things is wrong; a second reader is bought with **opposing stance** over the same material, never by dividing it. Each finding is **restated without naming the reference before its direction is asked**, so a reference that can demolish a claim resting on it does not get used to erect one about your design — what survives is a defect, what does not is a proposal and is labelled one. Then graded `CONFIRMED` / `UNADJUDICATED` / `INERT` / `DELIBERATE`, because a pass returning bare claims costs more after it finishes than while it runs. Citations are re-opened at the source, never transcribed. Model-invoked — `thegraph` is user-invoked and can only reach model-invoked siblings. |
| [`grill-map` v1](retired/grill-map-v1/) | **Retired — no longer installed; moved to [`retired/`](retired/), see [ADR-0082](docs/adr/0082-grill-map-is-rewritten-to-read-the-repo.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** The first `grill-map`: authored a repo's **MAP** by measuring first — public-surface counts, record greps, file-size distribution — and called a note done when a checker passed, which verified addresses and not claims. Rewritten under the same name (next row); it lost the first blind comparison on `justerm`, then won after fixes there and on a held-out repository. Kept readable because the maps it wrote still exist in other repositories; the rewrite reads them as leads. |
| [`grill-map`](grill-map/) | Author a repo's **MAP** by **reading the repo the way a person learns a codebase** — README and identity docs, glossary and decision records, the folder tree as a reading guide, the entry points, and always the open backlog — and **asking when the reading does not explain something**. Grep and counts settle a doubt the reading raised; they do not open the run. Every claim carries its evidence, or its source and date when nothing in the repo can confirm it. The mode is read from disk: **init** writes the map from scratch and stamps the hub with the commit it was synced at; **update** reads the commits and backlog since that stamp the way a maintainer back from leave reads the log, rewrites only the claims they falsified, makes each fact that gained a second copy one owner and pointers, and recommends a fresh init when the structure moved. Over an existing map — a `grill-map` map or a folder of hand-written notes — init drafts from the system first, then reads the old notes as leads: each claim is re-verified, attributed, moved or dropped with a reason, a concept that survives keeps its note path so the comments pointing at it still land, and every reference that changed meaning is listed for repointing. It surveys the map and asks first, and can instead **adopt** it: stamp it at its last commit and update from there. Done is a **reading test** — the map alone explains a real change — not a checker passing. It replaced the first `grill-map` under the same name after blind comparisons on two repositories (ADR-0082). |

| `sift` | **Retired and deleted from the tree, see [ADR-0075](docs/adr/0075-sift-is-retired.md) and [ADR-0027](docs/adr/0027-retirement-moves-a-skill-to-the-retired-folder.md).** Decided where each comment paragraph belongs across seven dispositions, three of which stayed in place on the ground that some knowledge is only enforced by sitting where it sits; carried the L1/L2/L3 guard layers for a measured constant and twenty worked fixtures. The maintainer took the one-bin policy; the comment rule in `CLAUDE.md` now carries it, and `decant` retired too (ADR-0092). |
| [`plat`](plat/) | Which directory owns what, decided by reading what the named peers actually did — the layout half [ADR-0037](docs/adr/0037-placement-is-a-node-because-the-alternative-was-four-files.md) scoped out of `thegraph`'s `place` node, extracted because its two reasons were reasons not to *store* a peer's tree and neither was a reason not to **compare** ([ADR-0040](docs/adr/0040-the-peer-comparison-is-a-method-and-leaves-as-plat.md)). Layout is where a seam is **physically** expressed, so a file in the wrong directory breaks the seam while producing no error, no failing test, and no warning. Proposes the peer set with evidence and **stops until a human confirms it** — a builder that picks its own peers has invented the authority it then defers to — then reads their **real trees**, never a write-up, because a layout off a documentation site is *summarized* and can never confirm anything. Compares on **role, not name**: a different name for the same role is no difference, and the same name for two roles is the one that bites. Every difference is classified **adopt** / **deliberate divergence** / **unclassified**, and the unclassified bucket is the output — a difference nobody decided is drift wearing a rule's clothes, and majority is evidence, never authority. Emits the tree rule as concrete paths and the divergence list with a reason each, then **stops**: it moves no file, because a move made before the rule is written drifts straight back. Answers the case a compile cannot reach — a project with **no tree yet** — from the project's identity plus the confirmed peers, marked provisional. Nothing invokes it; a person runs it when the tree is the question. |
| [`blog-it`](blog-it/) | Turn what a session already worked out into a published blog post, in the author's voice, **from whatever repository the author happens to be in** — which is where the decision to write actually gets made. Substance comes from the conversation and nothing is re-researched, because re-researching produces a survey of the topic rather than a record of the work. **One line governs it**: technical content established in the session is fair to write up, while opinions, evaluations and surprise belong to the author and are taken from what they actually said — where the session holds none, the gap is left visible or one question is asked, never filled, since a post the author cannot defend is worse than no post. The genre is settled per run rather than templated. Drafts go to a temporary place and never into the repository in hand, and source quoted out of that repository is approved before anything is published — it may be private, licensed, or someone else's, and publishing is irreversible. Publishes Korean and English under one slug, because the post list joins strictly on language and a single translation is absent from the other list entirely. Calls `jblog`, the blog's own CLI, which stays in the blog's repository ([ADR-0072](docs/adr/0072-blog-it-lives-here-its-command-lives-in-the-blog.md)) — the tone notes' path, the site's address and its vocabulary are **answers that command gives**, so none of them is written down here where nothing could check them. |

## Install

To sync the skills and the mods in one go — `--dry-run` previews both, and
`--claude` or `--codex` limits the skills to that agent:

```sh
./scripts/sync.sh                  # runs install-skills.sh, then install-mods.sh
```

Each script below also runs on its own, and takes the flags only it knows.

Link every skill in this repo into both `~/.claude/skills` and
`~/.codex/skills` (or `$CODEX_HOME/skills` when `CODEX_HOME` is set):

```sh
./scripts/install-skills.sh        # macOS / Linux / WSL / Git Bash on Windows
```

To sync only one agent, add `--claude` or `--codex`.

The script scans the repo for every folder containing a `SKILL.md`, so new
skills are picked up automatically on re-run. It creates links — a directory
junction on Windows, a symlink on Unix — not copies, so edits made in this
repo are live in both agents immediately. No Developer Mode or elevation is
needed.

It also links [`docs/environment/CLAUDE.md`](docs/environment/CLAUDE.md), the
maintainer's user-level instructions, to `~/.claude/CLAUDE.md` and
`$CODEX_HOME/AGENTS.md`, so every session on the machine loads it. A real file
already there is reported and left alone; `--replace-copies` moves it aside. On
Windows that link is a file symlink, which needs Developer Mode.

Skills install into both agents by default. Put `codex` or `claude` on separate
lines in `agents/install-targets` to restrict a skill to those targets; the next
sync removes any repo-owned link from the other target.

**A real folder sitting where a link belongs is reported as `SHADOWED`.** That
folder is what Claude Code loads, so edits here are *not* live for it — which is
silent, and is how four skills once ran for days against a stale copy of
themselves after a rename. The run says whether the shadow's `SKILL.md` differs
from this repo's and carries the count into its summary line, so a run that
skipped skills cannot read as a clean one. Nothing is removed by default; add
`--replace-copies` and the folder is **moved** to
`~/.claude/skills-replaced/<name>-<timestamp>`, never deleted — the script
cannot tell an old copy from one somebody edited in place, and moving is the action
that does not need that judgement.

Re-running is a **sync**, not just an add: a skill that was deleted, renamed,
or merged into another bundle leaves a stale link behind, and the script
prunes it. Only links pointing back into *this* repo are ever removed — links
that other skill repos put in `~/.claude/skills` are left untouched. Pass
`--dry-run` to preview the changes without touching
anything.

## Adding a skill

1. Create a folder at the repo root containing a `SKILL.md`. Use the
   `write-a-skill` skill, or copy `to-html/` as a template.
2. Re-run the install script to symlink the new skill.

## Mods

`mods/` holds Claude Code mods — plugins of function hooks, not skills. This
repo is also a plugin marketplace that lists them, and one script installs them
all for every session:

```sh
./scripts/install-mods.sh          # macOS / Linux / WSL / Git Bash; --dry-run, --uninstall
```

From another machine, without cloning: `/plugin install <mod> --marketplace kihyun1998/skills`.
Adding a mod, its layout, and the check every mod passes: [`mods/README.md`](mods/README.md).

| Mod | What it does |
| --- | --- |
| [`usage-band`](mods/usage-band/) | Two rows above the prompt in three divided columns, each a head over its gauge: context (model, effort, the prompt cache's hit rate), the 5-hour window (`%/h`, or when it runs out if before the reset, and its reset) and the week (with today's cost and `$/h`). Quiet until something needs saying: colour only for a limit past 80%, a pace that runs out, a cold cache, a heavy day. Replaces the ccusage statusline; see [`docs/environment/usage-band.md`](docs/environment/usage-band.md). |
